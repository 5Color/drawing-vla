# Hand vs AI: 인터랙티브 라이브 스케칭 & 생성형 AI 대안 패러다임 명세서

> **"통짜 픽셀을 찍어내는 디퓨전의 시대를 넘어, 인간의 창작 과정을 실시간으로 재현하고 협업하는 제3의 생성 모델(Generative Trajectory Model)"**

---

## 1. 프로젝트 개요 및 핵심 철학

### 1.1 프로젝트 정의
`Hand vs AI`는 인간의 드로잉 궤적(Trajectory: $x, y, t, \text{pressure}$) 시연 데이터를 웹 게임(대결 및 랭킹) 형태로 수집하고, 이를 바탕으로 인간처럼 자연스럽게 선을 긋고 협업하는 드로잉 AI를 구축하는 프로젝트이다.

### 1.2 최종 목표와 비전의 재정의: 디퓨전(Diffusion)의 실질적 대안
* **기존 생성형 AI(픽셀 디퓨전)의 한계:**
  * Midjourney, Stable Diffusion 등 현재 주류 모델은 인터넷의 방대한 정적 이미지를 긁어 노이즈를 제거하는 픽셀 회귀 방식에 머물러 있다.
  * 이는 결과물만 툭 뱉어내는 블랙박스로, **과정의 부재**, **극심한 통제 불가능성(Uncontrollability)**, **수정 불가능성**이라는 근본적 한계를 지닌다.
* **Hand vs AI의 궁극적 비전:**
  * 픽셀(Pixel) 공간이 아닌 **액션(Action/Trajectory) 공간**에서 작동하는 새로운 생성형 모델 패러다임을 확립한다.
  * 단순히 "완성된 그림"을 주는 AI가 아니라, **"사람이 그리듯 10~15초 동안 캔버스 위에서 실시간으로 스케치를 구축해 나가는 라이브 드로잉 AI"**를 실현하여 생성형 AI 시장의 판도를 전환한다.
* **현실적 지향점:**
  * 물리 로봇 팔은 장기 탐색 과제로 두고, **순수 웹 소프트웨어와 실시간 캔버스 엔진에 집중**한다.
  * 고가의 커미션이나 복잡한 툴 없이도, 손재주가 없는 일반인이 아이디어를 직관적으로 구체화할 수 있는 **실시간 드로잉 코파일럿(Co-Drawing Copilot)**을 구축한다.

## 2. 생성형 AI 패러다임 전환 (Why Trajectory Beats Pixel Diffusion)

### 2.1 픽셀 디퓨전 vs 시계열 궤적 생성 모델 비교

| 비교 항목 | 기존 픽셀 디퓨전 (Midjourney, SD 등) | Hand vs AI (시계열 궤적 생성 모델) |
| :--- | :--- | :--- |
| **생성 공간** | 2D 래스터 픽셀 그리드 (RGB) | 시간 연속적 벡터 좌표계 ($x, y, t, \text{pressure}$) |
| **생성 과정** | 5~10초간 불투명한 로딩 바 대기 | **10~15초 동안 펜촉이 사각거리며 그리는 실시간 시각화** |
| **체감 지연시간** | 지루한 대기 시간 발생 | **첫 획이 수 밀리초($ms$) 안에 시작되어 체감 지연 = $0$** |
| **수정 및 통제** | 국소 수정 불가 (인페인팅 시 전체 훼손) | **선 단위, 획 단위, 레이어 단위의 완벽한 벡터 수정** |
| **인간-AI 협업** | 완료 전까지 인간 개입 불가 | **AI가 그리는 도중 멈추고 인간이 이어 그리기 가능** |
| **확장성** | 해상도 고정, 확대 시 픽셀 깨짐 | **무한 해상도 벡터(SVG), 애니메이션 숏폼 자동 변환** |

### 2.2 디퓨전 생성 시간의 3배(10~15초)가 완벽한 '스위트 스팟'인 이유
* **과정 자체가 곧 엔터테인먼트:** 
  * 디퓨전에서 15초 대기는 답답한 로딩이지만, 캔버스 위에서 뼈대를 잡고 외곽선을 따나가는 15초는 사용자가 몰입하여 감상하는 **라이브 드로잉 ASMR이자 쇼츠 콘텐츠**가 된다.
* **인간적 호흡(Human Dynamics)의 구현:**
  * 1초 만에 기계적으로 선을 출력하는 오토트레이서와 달리, 곡률에서의 감속, 스트로크 간의 손 뗌, 펜 가속도 등 인간의 손놀림 리듬이 살아있는 결과물을 만든다.

## 3. 핵심 킬러 기능 (Core Features)

1. **프롬프트 기반 라이브 스케칭 (Prompt-to-Live-Sketch):**
   * 프롬프트를 입력하면 AI가 실시간으로 10~15초에 걸쳐 러프 스케치부터 디테일 펜선까지 순차적으로 드로잉 스트리밍.
2. **실시간 중간 개입 & 합작 모드 (Interactive Co-Drawing):**
   * AI가 얼굴형을 그리는 도중 [일시정지] 후 사용자가 안경이나 모자를 직접 그어주면, AI가 해당 획의 문맥을 인식하고 자연스럽게 이어 그림.
3. **일반인을 위한 실시간 획 보정 (Stroke Stabilization & Autocomplete):**
   * 손재주가 없는 유저의 삐뚤빼뚤한 선을 인간 최고 수준의 부드러운 곡선(Spline)으로 실시간 유도 및 다음 연결선 가이드 제시.
4. **순수 벡터(SVG) 기반 레이어 분리:**
   * 완성 후 "스케치 레이어 숨기기", "외곽선 두께 0.5px로 변경" 등 그래픽 툴과의 완벽한 호환성 제공.

## 4. 시스템 아키텍처 및 데이터 전략

### 4.1 모델 발전 로드맵
* **현재 (Step 1): 경량 MLP 모방학습 (Behavior Cloning)**
  * 초기 소규모 데이터(50~100개 수준)에서는 노이즈에 취약한 디퓨전(F1: 0.878)보다 MLP(F1: 0.982)가 오차와 브라우저 연동 속도에서 압도적 우위.
* **중기 (Step 2): 2-Stage Hierarchical Model (Planner + Motor Policy)**
  * **High-Level Planner:** 전체 도안의 핵심 앵커(Keypoints)와 스트로크 구조를 1초 내 설계.
  * **Low-Level Motor Policy:** Action Chunking을 통해 인간의 부드러운 손놀림 궤적을 30~50Hz 단위로 프론트엔드에 스트리밍.
* **최종 (Step 3): Foundation Generative Trajectory Model**
  * 대규모 인간 궤적 데이터 기반의 자귀회귀(Autoregressive) 및 Diffusion Policy 융합 아키텍처 구축.

### 4.2 데이터 파이프라인 원칙
* **원본 데이터 불변성(Raw Immutability):**
  * 수집된 raw JSON 데이터는 손상 없이 원형 보존.
* **`dataset.py` 온더플라이 정규화:**
  * 사용자에게 그리는 순서나 방향을 강제하지 않고, 로더 단계에서 기준 도안 벡터와 비교하여 방향 반전(`[::-1]`) 및 획 순서를 동적으로 정렬.
* **모더레이션 필터 (`tools/moderate.py`):**
  * 1초 미만 초고속 광클, 커버리지 미달, 매크로성 좌표 주입 건은 `suspect`로 격리하여 모델 오염 원천 차단.

## 5. UX 원칙 및 데이터 윤리

### 5.1 자연스러운 손맛을 살리는 UI
* **강제 가이드 배제:** 깜빡이는 화살표나 선 강조 효과를 전면 배제하여 "학습지 따라쓰기" 느낌 제거.
* **미니멀 넛지:** 첫 획 시작점에만 **연한 점(•) 하나**를 은은하게 두어 자연스러운 시작 유도 (터치 즉시 소멸).
* **2초 시범 온보딩:** 첫 방문 시 사람이 그리는 시범을 2초간 보여주되 캔버스 터치 시 즉시 스킵.

### 5.2 투명하고 거부감 없는 안내
* **법적 성격:** 실명, 연락처 등 개인식별정보(PII)를 일절 수집하지 않는 익명 연구 데이터.
* **거부감 없는 푸터 문구:**
  > *"실시간 랭킹 등록 및 AI 대결 기능을 위해 플레이 궤적이 저장됩니다. [내 기록 삭제]"*
* **기기 기반 셀프 삭제:** 유저가 브라우저 버튼 클릭 한 번으로 본인의 기록을 Supabase에서 즉시 지울 수 있도록 구현.

## 6. 최근 코드베이스 안정화 내역 (Changelog)

* **대시보드-모더레이션 쿼리 동기화:** `status` 조건 일치로 격리된 의심 건 누락 해결.
* **동시성 버그 수정:** 채점 중 캔버스 조작 시 리플레이 꼬임 현상 및 지연 응답에 따른 첫 획 삭제 방지.
* **정밀도 누락 보정:** 터치를 뗄 때 마지막 접촉 타임스탬프 기록 누락 수정.
* **데이터셋 누수 차단:** 손상 파일 스킵 시 Validation 데이터가 Train 세트로 섞이는 문제 해결.
* **리더보드 기준 통일:** 유저/기기별 최고 기록 기준으로 순위표 집계 일원화.
